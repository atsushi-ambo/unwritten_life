# 質問に答えて始める

トップの「質問に答えて始める」から、簡単は1画面、詳しくは「現在／これから」の2画面、さらに詳しくは「暮らし」を加えた3画面で関連項目をまとめて入力する。詳しさを選ぶだけの画面や独立した確認画面は置かず、画面内の選択で切り替える。最終画面に要約と開始ボタンを置く。補足は折りたたみ、入力済み件数を表示する。選択しただけでは移動せず、まとめて確認して「次へ」で進む。戻る・閉じるで入力は残る。元のフォームを唯一の正本にし、質問画面は値を同期するだけ。簡単・詳しく・さらに詳しくの条件表示を引き継ぎ、最後は既存フォームの検証と開始処理を使う。家計の内訳など残りの項目は「一覧で細かく調整する」から編集できる。保存形式・計算・AI課金設定は変更しない。

## 会社情報

Wikidataで公式URLが未登録でも会社を候補から消さない。日本語Wikipediaの記事があるときは、そのinfoboxの公式サイト欄と会社概要も参照する。記事の本文中にある一般リンクや、推測したURL・親会社への置換は使わない。会社名と候補ホストを本人が確認した後だけ、PC版は公式本文を取得する。会社トップの場合、同一オリジンの会社名に対応する会社概要リンクを最大1件辿る。各取得で既存の公開HTTPS・DNS・リダイレクト・時間・容量制限を使う。

事業内容・取得元URL・根拠がある業界を自動入力する。既に本人が指定した別の業界は上書きしない。職種や本人の年収・待遇は会社の概要から推測しない。遅い応答で手入力や別の会社を上書きしない既存の世代管理を維持する。内容を物語へ採用するチェックは本人が行う。公式本文が取得できない場合はWikipediaの概要だと明示する。スマホ版はWikimediaの固定APIだけを呼び、第三者の会社サイトをブラウザから直接取得しない。記事HTMLは不活性なtemplate内で解析し、表示はtextContentで行う。

## 音声

住所の市区町村、会社名、仕事内容、職歴・希望のテキスト欄だけが対象。金額・数値は対象外。SpeechRecognitionの端末内処理に対応する場合はそれを既定にする。非対応や日本語の言語モデルがない場合に勝手にオンラインへ切り替えず、音声送信の説明と明示的な許可チェックを必要とする。チェックは欄を移るとリセットする。未対応ブラウザにはOS・キーボードの音声入力を案内する。APIキー・音声用のAPI課金は不要。

ボタンを押すまで開始せず、自動送信・自動遷移もしない。移動・閉じる・手入力・ページ非表示でabortし、世代と対象欄の一致しない遅い結果を破棄する。職歴など複数行の欄では既存の文章に追記する。録音や音声データを保存しない。Permissions-Policyはマイクをselfだけに許可し、カメラ等は従来どおり拒否する。

自動検証は合成の認識イベントを用い、実際の音声や個人プロフィールは使わない。実機のマイク権限・認識エンジン・日本語パックの動作確認とは区別する。
