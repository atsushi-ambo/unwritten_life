# 公開用ソースの確認

公開するのはソースコードと合成データだけ。所有者や利用者の住所、勤務先、職歴、実際の年収・資産、セーブ、音声、APIキー、ローカルの絶対パスは、入力例・テスト・説明・配布物に使わない。職種や企業名を扱う機能そのものと、所有者の情報を例に使うことは区別する。

## 公開する内容

公開候補は、検証した現行ツリーから作る履歴なしの独立したスナップショット。コミット作成者はGitHubの公開アカウント名とnoreplyメールだけを使う。元の履歴は公開候補へ持ち込まない。元リポジトリの非公開保管や置き換えは、所有者が内容と影響を確認した後に行う。既に他の人が取得したコピーや検索側のキャッシュまで消去できるとは保証しない。

GitHubは閲覧用公開、IssueとDiscussionsは無効、PRの作成は共同管理者だけに限定する。所有者以外へ共同管理権限を付けない。秘密情報検知・push保護と、既存のSHA固定の共通CIを使う。コードはMITライセンスとし、モデル等のライセンスとは区別する。

## 検証

`npm run check:release` は単体検証、開発用を含む依存検査、Git全履歴と現行ファイルの秘密情報検査、Workerビルド・型・拒否経路、PC/スマホ/WebKitの操作検証を行う。プロフィール・AI応答・音声認識イベントは合成データを使う。秘密情報スキャンは個人情報の自動検知の代用ではないため、個人に結びつく例・絶対パス・通常メール・追跡対象ファイルも別に確認する。

配布するモバイルアセットは固定の公開ファイルだけ。出力先は作成前にシンボリックリンクを解決し、ソースやGit内部、依存ディレクトリへの出力を拒否する。

## 実行時の境界

PC版はループバックだけで待ち受け、Host・Origin・CSRFトークン・JSON形式・回数を検証する。静的配信は許可リストだけ。外部ページ取得は公開HTTPS、DNSで解決した接続先、各転送先、時間・容量を制限する。CLIは固定実行ファイルと許可した引数をシェルなしで呼び、資格情報を読んだりコピーしたりしない。

スマホWorkerは本人限定の配備境界と、基盤による認証ヘッダーの上書きを必要とする。さらに `OWNER_USER_ID` と `UNWRITTEN_ORIGIN` をサーバーで設定し、欠けた設定や別の利用者はDBやAIへのアクセス前に拒否する。個人の配備URLをソースに埋め込まない。公開用の任意Workerとして認証ヘッダーだけを信頼して配備しない。

この確認はコードと合成環境に対するもので、スマホ本番サイトの配備・課金・実データ更新を意味しない。音声はブラウザ依存で、実機マイクの認識精度は未確認。レビューや検査だけで安全を保証しない。
