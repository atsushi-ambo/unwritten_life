# 端末内の知識DB

> 2026-10-19追記：このゲームはAIの接続を必須にしました。毎年の場面・4択・転職候補はすべて接続したAIが本人の入力から作り、ルールで用意した選択肢、手動のJSON交換、内蔵の企業リスト（公式事業情報7社とキンドリル2社）は廃止しました。接続先（ローカル・サブスクCLI・API）はどれでも毎年自動で生成し、クラウドは接続時の送信同意が必要です。一度提示・在籍した企業はセーブの `careerSeen` と `pastCandidates` でAIに渡し、繰り返さないよう指示します。以下の記述のうち、手動交換・ルール候補・内蔵企業・クラウドの手動生成に関する部分は旧仕様の記録です。 知識DBは歴史8件とゲームの仮定9件になり、版は `2026-10-19.1` です。


固定した知識の参照にLLMは使わない。ユーザーの入力・選択・確定した結果が変わる部分に、計算とAI生成を使う。確認済みの知識を保管・検索する仕組みであり、モデルの重みを追加学習する機能ではない。

## 資料と保存先

`public/world.js` の `KNOWLEDGE` が確認・版管理する原本。2026-10-17.1版は歴史・普及の観測8件、企業の公式事業概要7件、ゲームの仮定9件。全世界史を網羅する資料ではない。歴史には期間・対象・出典URL・確認日、企業には確認日時点の概要を持つ。仮定には `game-rule` を付け、実測や統計と扱いを分ける。企業概要は `careers.js` の原本から作り、二重に管理しない。

PC・スマホともブラウザのIndexedDB `unwritten-life-knowledge` に保存する。`records` は安定IDを主キーに資料を持ち、`meta` はカタログ版と件数を持つ。初回に原本を登録し、再読込時はDBを読み、原本と一致することを確認して利用する。古い版・改変・未確認の追加は、このDBの資料ストアだけを原本から再構築する。セーブは従来の任意保存のまま分離する。プロフィール・選択履歴・プロンプト・AI生成の物語は、このDBには保存しない。

アプリを開く各origin・ブラウザごとに独立する。PCのファイルに集約したSQLiteや、全員が共有するクラウドDBではない。DBを利用できない・保存容量がない・2.5秒を超える場合は同梱資料へ切り替える。ブラウザがDBを削除した場合も次回初期化できる。ブラウザのデータ削除はセーブも消し得るため、知識更新を理由にブラウザ全体のデータを削除しない。

## その年の参照

`knowledgeFor(game)` が、検証済みのゲーム状態から職種、仕事の形、家族、住居、直前の行動、直前の景気・世界の局面をタグへ変換する。自由入力のタグやAIの指示で検索条件を上書きできない。関連度と固定順で最大2件の歴史、現在の企業に一致した最大1件の概要、最大4件のゲーム前提（転職比較では3件）を選ぶ。学習、起業、家族、転居などの選択をすると参照内容も変わる。資料集を毎回全部送らない。

ブラウザの手動交換と情報プレビューはDBから読んだカタログを使用。PC/APIサーバーは同じ版の同梱カタログを参照し、ブラウザから任意の知識を受け取らない。クラウドAIで物語を作る場合には選んだ資料もプロンプトに含むが、検索そのものにAPI呼び出しはない。AI未接続でも収支・成功失敗・世界・家族の計算や分岐は動く。

2026年時点の企業資料は2050年にも当時の記録。2050年の公式発表ではない。過去のパンデミックや景気の谷を未来の同じ出来事として再発させない。資料は背景を考える参考で、ゲーム係数の自動推定や現実の寿命・給与予測には使わない。プレイヤーの選択と数値結果の正本はゲームエンジンで、知識の更新で過去の収支や乱数を変更しない。

## 更新と検証

1. 一次資料を確認し、必要な事実だけを短く要約する。ページ本文・画像の一括転載はしない。
2. `world.js` の資料に固有ID・期間・出典・確認日・検索タグを追加。実在企業の概要は `careers.js` を編集。仮定は `game-rule` にする。
3. `KNOWLEDGE_REVISION` を更新。件数が変わる場合はREADMEも更新。
4. `npm run check` と `npm run audit` を実行。ブラウザ版は `npm run build:mobile` で同じ資料を含める。

DBの再読込、古い資料・未確認の追加の修復、保存できない場合の継続、入力や選択による資料の違い、履歴の復元、AIへ渡る上限を自動検証する。IndexedDBの単体検証にはテスト専用の `fake-indexeddb` を使い、実ブラウザの保存・表示確認とは区別する。

実装は [W3C Indexed Database API](https://www.w3.org/TR/IndexedDB/) に沿ったオブジェクトストアとトランザクションを使用する。自動のWeb巡回、ユーザーの個人情報による学習、AI生成の事実登録は行わない。
