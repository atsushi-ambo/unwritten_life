# プロフィールを、場面と次の選択へつなぐ

PCとスマホは同じ `public/engine.js` の処理を使う。プロフィールから現在の場面の話題を選び、その話題に合う実行可能な4択を作る。新しい外部通信・プロフィールの保管先は追加しない。

市区町村・具体職種・業界・仕事内容も任意で入力できる。市区町村は端末内の場面とAIの `life.municipality` へ渡し、ゲーム内の移動後は現在地として使わない。仕事と業界は開始時の話題となり、AIの `workplace.startingWork` に本人入力として残す。転職後の現職へ開始時の業界を上書きしない。職種の細分化や地名そのものによる数値加点・相場の推定はしない。

| 入力・現在の状態                           | 場面・選択への使い方                                                                                                         |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| 職歴・希望メモ                             | クラウド、運用、データ、発信、創作、英語などのキーワードを話題へ。経験や熟練度とはみなさない。未知の文章は短い引用として扱う |
| 確認した勤務先の事業                       | 現在の勤務先の事業背景と、自分の役割を考える場面。未確認の概要は使わず、転職後は新しい勤務先に切り替える                     |
| 現在の子どもの人数・年齢、パートナー、ケア | 実際のゲーム内の家族に応じ、時間配分・相談・仕事を抑える案へ。成人した子に幼児の世話を設定しない                             |
| 家族の希望                                 | 支えや暮らしの準備へ。希望だけで家族を増やさない                                                                             |
| 住居・ローン・地域・家賃                   | 挑戦と住居費の両立、維持の負担、地域を変える案へ。完済後は返済中と描かない                                                   |
| 現金・株式等・借入                         | すぐ使える資金と値動きする資産を区別。現金が生活費の半年分未満なら生活の立て直しを優先                                       |
| 退職の目安・現在の就労状態                 | 仕事を離れる準備や、その後の人・学び・時間の使い方へ                                                                         |
| 前の選択・意図・実際の成否                 | 年次エピソードと次の場面に引き継ぐ。5年続ける途中で選んだ学習テーマを変えない                                                |

一度に全項目を列挙せず、仕事の関心と暮らしの条件を組み合わせ、年ごとに話題を巡回する。行動できない案、重複する行動、成功や収入増の約束は作らない。事業の不調・撤退・生活の立て直し、前年の出来事から出た寄り道を優先して残す。使った入力は場面の折りたたみ欄と各選択肢の「あなたとの接点」に表示する。

## 端末内の生成とAI

端末内とAIのどちらも、キャリアと人生のシミュレーションとして語る。各場面は現在の仕事や経験、次の働き方、退職後の暮らしを軸に、家族・お金・住まいとの迷いを描く。AIの通常モードでも4択すべてを転職や仕事の案にはせず、転職比較モードは従来どおり3社と残留案（求職中は休養）を比べる。実在の求人サイトのブランド名は使わない。入力の未信頼扱い、採用や給与の創作禁止、計算済みの収入・赤字・家族との整合、出力形式と文字数の制限は維持する。

端末内の自由文処理はキーワードによる限定的なもの。「AWSは未経験」とあっても経験者とはしない。「使いたくない」「興味がない」などの明示的な否定のある文は、その話題の抽出から外す。あらゆる否定・文脈・言語を理解する自然言語モデルではない。認識できない内容は希望や経験と決めつけず、引用したメモとして残す。

AI用の `storyRequest()` はメモの全文、現在の家族・住居・資産、確認した企業資料、過去の実際の結果に加え、端末内で選んだ話題と入力元を渡す。単なる列挙ではなく、複数の条件を一つの迷いと4択に結びつけるよう指示する。メモや企業資料中の命令は実行しない。数値結果は従来のエンジンが決め、文章量やキーワードから能力・確率・待遇を加点しない。

スマホ静的版のAIは手動JSON交換のまま。端末内で変化する場面を、LLMが自動で書いたものとは表示しない。以前に取り込んだAIの場面は勝手に書き換えない。

## 検証

`npm run check` に、同じ職種でも職歴メモで場面と4択が変わること、各案の実行、家族の年代・希望・ローン・現金不足、会社資料の確認と転職後の切替、複数年の意図保持、保存復元、メモによる数値加点がないことを含める。

2026-10-17にローカルOllamaの `gemma4:12b-it-q4_K_M` で合成プロフィール1件を実生成。AWS・受託/SIの経験、3歳の子、持ち家・住宅ローンを本文と4択に反映し、実行可能な構造として検証できた。約36秒、入力3701・出力456token。API課金なし。全プロフィールや全モデルの生成品質を保証する検査ではない。生の合成出力はGit対象外の `artifacts/profile-story-ollama.json` に保存した。
