# 初版の設計とモデル v0.1

## 目的と境界

現在の自分を主人公に、仕事・暮らし・関係・自由の配分を遊びながら考える。AIへの対応だけで成功が決まる設計や、年収だけを勝敗にする設計を避ける。

利用者は自分のブラウザ内のプロフィールを編集し、選択・巻き戻し・比較・保存削除ができる。他人のプロフィールを取得・更新する機能、公開投稿、ログイン、決済はない。GitHubへ入れるのはコードと合成テストだけで、実際の人物の入力は入れない。

初版の対象は日本語・国内3地域の簡略モデル、開始年齢18〜80歳、開始年2026年、期間20年。2026年10月17日に確認した情報と、将来の仮定を区別する。

## 入力の量

基本の6項目は年齢、地域、仕事内容、年収、AI利用経験、大切にしたいこと。初期値を編集でき、架空の人物でも開始できる。任意で性別、暮らし、貯蓄、月間生活費、勤務先タイプ、会社名を指定する。

職業は個社でなく8つの仕事内容の分類。会社名と性別は表示のみ。勤務先タイプも表示のみで企業の予測には使わない。暮らしは地域別の生活費初期値の倍率に使い、同じ生活費を指定した場合、世帯の形で結果を不当に変えない。任意の入力欄を開かなくても、貯蓄・生活費の初期値を表示する。

## 処理と保存

入力 → 型・範囲・列挙値検証 → 初期状態 → 年次の選択 → 次状態 → 画面、という流れ。`engine.js` はDOMに依存せず、画面や保存から渡されるデータも検証する。

任意保存はプロフィール、シナリオ、seed、選択列、モデルバージョンだけ。保存された計算結果は信じず、復元時に再計算する。文字列容量12KB、選択20件を上限にする。将来のモデルバージョン変更時は移行を明示的に設計し、未対応データを黙って別モデルで再解釈しない。

表示は `textContent` とDOM生成で行い、入力をHTMLとして解釈しない。プロフィールをURL・アクセスログに出さない。フォームの標準送信はCSPでも拒否し、クライアント以外にプロフィールの受信経路を用意しない。

HTTPサーバーは127.0.0.1だけにbindし、Hostをlocalhost/127.0.0.1に限定。許可した5ファイルとトップページだけを配信する。GET/HEADのみ。認証・DB・外部URL取得・アップロードを必要としない初版なので、それらの仕組みを追加しない。

## AIのモデル

ILOの研究から参考にしたのは、職業の中のタスクの変化、AIによる補完と置き換えの区別、曝露指標を失業予測と同一視しないという考え方。以下の数値はすべて独自の遊びの仮定で、ILOの統計値や将来予測値ではない。

- 普及速度係数：slow 0.46、steady 0.74、fast 1.08。各シナリオに起こる確率はない。
- 普及指標：`clamp((0.12 + 経過年数 × 0.037) × 普及速度, 0, 0.95)`。
- 補完による利益：`普及指標 × 職種別補完係数 × (AIスキル/100) × 0.10`。
- 移行負担：`普及指標 × 職種別曝露係数 × (1 - AIスキル/125) × 0.075`。
- 年収変化率：基礎0.6% + 共通の年次変動±3.5% + 補完利益 − 移行負担 + 仕事集中の2.3% − ゆとり指標30未満の3.5%。最終的に±12%へ制限。
- 職種別係数と、各選択の費用・指標への影響は `public/engine.js` の `JOBS` / `CHOICES` を唯一の定義とする。

3世界比較では初期値・選択・seed・年次の偶然を固定し、AI普及速度のみ変える。比較は利用者が実際に選んだ年数分で、未選択の将来を選んだかのように扱わない。健康・つながり・自由の指標はAIシナリオから直接変化させず、選択と価値観から変わる。差が出ない項目があることも表示結果の一部。

## お金と暮らし

金額は万円、2026年の購買力。各年の貯蓄変化は `年収 × 0.76 − 生活費 × 12 − 選択費用 + 挑戦の偶然収支`。可処分所得率76%は税制の計算ではない。挑戦の偶然収支は±15万円、運用収益は0とする。初期年収0なら、年収成長率だけで架空の収入を生み出さない。

年齢は表示年齢・時間軸に使う。退職・年金・病気・死亡をモデル化しないため、高齢期の収入等も現実の推計ではない。健康等は診断ではなく0〜100の表現。家族やジェンダーによる決めつけを避け、結婚・出産・昇進を強制する進行は設けない。

## 検証と更新

`npm run check` をローカル・CIで共用。入力の正常/拒否、キャッシュ・パス・Host・更新拒否、20年終了、全職種×シナリオ×選択、収支の算術、比較の同条件、巻き戻し、保存データの再検証を確認する。実データ・秘密情報・課金APIは不要。ブラウザでは入力・デモ・20年進行・比較・巻き戻し・端末保存/再開/削除・モバイルを確認する。

CIの権限は `contents: read` のみ。PRコードには秘密情報を渡さない。外部ActionsはSHA固定し、Dependabotで更新。週次・手動でも同じ検証とnpm auditを実行する。現在は追加パッケージ0件のため、npm auditの対象が小さいことを結果とともに示す。

公開前にはHTTPS、配信ヘッダー、公開データ、実機とアクセシビリティ、仮定の明示を確認する。保存形式を変える場合は既存データの移行と削除を確認する。現時点でアプリの一般公開やユーザーデータのバックアップ同期は行わない。

## 次に広げるなら

章ごとの転職・学習・移住などの具体的な選択、場面のバリエーション、仕事内容に合わせた物語、より現実的な家計モデルを優先する。外部LLMによる物語生成を追加する場合は、送信項目・保存期間・費用・出力検証を別途設計する。公開の個人プロフィールやランキングは初版の要件ではない。
