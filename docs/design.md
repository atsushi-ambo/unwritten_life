## 目的と権限

2026年の自分から、入力と選択で変わる生涯を遊ぶ。アプリは家計・状態・時間の進行を、LLMは入力や履歴に合う架空の場面と選択肢を担当する。AIの追加を予測精度の保証として扱わない。

利用者は自分のブラウザのプロフィール、選択、生成場面の保存・削除を行える。公開投稿・他人のデータへのアクセス・決済はない。PC版はローカルサーバーで動かし、APIキーは起動中のメモリに限定する。スマホ版はSitesの本人限定認証を使うWorkerで動かし、キーはサーバーの秘密情報として管理する。外部AIや取得ページにPCの操作権限は与えない。

## 入力と状態

2026-10-20更新：年代（20〜60代）と地域からゲーム用の金額を決めて開始でき、家族は中立の初期設定にする。基本8項目を任意に調整：年齢18〜100、国内3地域、30種類の職種、税引き前年収、AI利用経験、価値観、金融資産合計、持ち家/賃貸等。任意で株式内訳、不動産評価額、住宅ローンと金利・期間、生活費、家賃、世帯、退職年齢、65歳以降の収入、会社タイプ・名前・公開資料を設定する。

金融資産合計から株式を引いたものを現金とする。初期金融資産が負なら、負の額をその他借入として扱う。純資産は `現金 + 株式 + 不動産 − 住宅ローン − その他借入`。住居の評価額は別枠。ローンは評価額と独立で、売却価格を借入から逆算しない。

性別は表示・計算・LLMプロンプトに使用しない。年齢は時間、退職、生活費、加齢、終了確率に反映する。会社名単独から業績や給与を予測しない。

## 年ごとの計算

金額は万円、2026年の購買力の仮定。税引き前年収の76%を使えるお金として、生活費×12、家賃またはローン元利返済・不動産維持費、行動費用、高齢期の追加費用を差し引く。76%は実際の税計算ではない。家賃と持ち家費用は二重に引かない。

従来の株式の年変化率は2.5%±17%（v0.3では国際情勢の補正を加える）、不動産は±3%のseed付き乱数。不動産維持費は評価額の年1%。配当・銘柄・税制・売買税・相続は再現しない。住宅ローンは月次元利均等の式を使い、12か月の利息・元金を順に計算する。固定金利とし、繰上返済は選択した年に残存期間を保って返済額を再計算する（期間短縮・手数料はモデル化しない）。

現金不足なら株式を必要額だけ売却する。それでも不足する分は、借入と仮定して不足を累計する。生活費半年分を超える現金から毎年自動返済し、残高に年2%の利息を加算する。現実に融資が承認されることを意味しない。破産・公的支援・生活保護はモデル化していない。

給与は基礎成長・年次変動・スキルによるAIの補完利益・移行負担・仕事への集中・ゆとり不足から変化する。従来の通常変化率は±12%内。v0.3ではこの制限後に景気・勤務先・国際情勢の補正を加える。転職では移行費用と追加の収入変化を適用する。昇給には職種・地域・会社タイプ別の目安（地方都市の基準：IT1400、マーケティング・営業1100、事務・制作1000、医療介護・現場750、自営1600、その他650万円。首都圏×1.2、郊外×0.85、大企業×1.15、中小・公的×0.9、自営×1.1、起業中×2。開始年収×1.3を下限）を置き、目安の半分を超えると成果・景気による増収分だけを指数的に縮める。減収は縮めないため、変動と高収入の可能性は残る。目安は実際の賃金統計ではなくゲームの仮定。退職年齢または退職行動で給与を0とし、65歳から入力した年金等を加算する。実際の受給条件・制度を再現した年金推計ではない。

## 入力と選択による分岐

転職では会社と職種を選ぶ。現在の勤務先・職種・会社タイプ・事業分野・出典を状態に持ち、給与・スキル・関係・自由と以後の場面を変える。以後は初期勤務先の資料を現職の事実として使わない。企業名自体に給与倍率は付けない。事業分類は公式資料を参考にしたゲーム側の分類、会社タイプは簡略化したゲーム設定であり、業績・AI導入実績・企業価値の評価ではない。資産配分は現金から株式へ振り替える。住居購入は地域別の仮の価格を使い、頭金20%・諸費用5%・借入80%とする。賃貸の地域変更では地域の生活費比率に応じ支出を変える。退職では給与が止まる。

AIの普及速度は3シナリオ。勤務先タイプからの導入係数と、利用者が確認した会社の事業分類を仕事の曝露係数に最大20%混ぜる。これらは会社の実測データに較正した推計ではない。初期勤務先の公開情報はAIの場面にも渡すが、出典のない将来の発表や解雇計画を事実として作らないよう指示する。

端末内で組み立てる場面の話題は、退職、資金不足、転職、AI普及、直近の選択、世帯と住まいに応じて変化する。ルールの選択肢はプレイ画面には表示しない。AIは現在の状態と直近4年の履歴から、具体的な場面・4つの選択肢を作る。行動IDはその状態で実行可能なものに限定し、ラベル・文章の型と長さ、重複を検証する。数値を直接指定させない。画面に行動の意味も併記し、生成ラベルと実際の処理を判断できるようにする。

2026-10-20追記（文体）：AIへの指示に文体の決まり（`SCENE_STYLE`）を加えた。ゲームや小説の地の文のような常体で、その人物に合った今年の一場面から始め、周りの人の短い一言を一つまで入れてよい（本人の言葉は作らない）。「直面する」「模索する」「新たな一歩」のような決まり文句や汎用の題を避け、迷いの一文で終える。内容の決まり（金額を書かない、赤字・減収・出来事の重さ、記録にない家族を作らない等）が文体より優先する。本文の目安は140〜240字。Claude Code（Haiku）で同じ3場面を比べると、変更前は「〜に直面しています」「最初の選択を前にしています」のような説明文、変更後は具体的な場面から始まる文章になった。

## 会社と事業の分岐

転職比較は、AIが本人の仕事の形・専門・勤務先・暮らしから3つの企業案と残留案を生成する。企業名を固定リストで制限しない。近い仕事の形の企業も含め、同業界を一律に除外しない。未生成時には候補を表示せず、生成に失敗した場合は再生成か接続の変更を待つ。通常イベントも同じ文脈の考え方で4択とし、構造化した企業・役割・事業・地域・具体的な意図を選択として保存する。根拠と実機検証は[本人の文脈から作る4択](personalized-choices.md)を参照。

新しい候補に固定の企業リストや内蔵の公式事業概要は使わない。`LEGACY_EMPLOYERS` の企業資料は旧セーブの再現用に残す。AIが挙げた企業・職務は未確認の提案で、求人・採用可能性・給与を調べた結果ではない。マーケティングの曝露・補完係数は企画職と同じ0.82/0.78というゲーム上の仮定を使う。

好きな実在企業の名前だけでも入力できる。追加資料を使う場合は既存の制限付きURL取得を使い、出典と企業の一致を利用者が確認する。企業名の検索は固定のWikidata APIで最大5件、公式サイトの候補は3件まで。古いURL・同名・子会社の可能性があるため候補とし、実際の本文を取得して利用者が確認する。LLMにURLを推測させず、取得先は既存の公開HTTPS・DNS・転送・容量制限を通す。APIキーや有料検索サービスは使わない。

転職は従来の収入変化に、同職種ならAIスキルに応じ最大2.5ポイント、異職種なら移行負担として−8ポイントを加える。現在の収入が0ならゲーム上の基準180万円を使う。以後は新しい職種・会社タイプと、事業分野20%の混合でAIの影響を計算する。実際の給与・採用難度・労働時間の推定ではない。

起業はAI支援・創作スタジオ・地域生活支援・小さな農園の4種。初期費用60/100/180/140万円、年間運営費24/36/60/48万円をゲームの仮定として表示し、初期費用を払える現金がある場合に選べる。初年度の労働収入は現在収入（0なら基準120万円）の30〜85%を基準に年次成長率で変動する。翌年以降は初期費用を再徴収せず運営費を徴収し、通常の成長率に±20ポイントの事業変動とAIによる需要・競争の仮定を加える。事業主の収入を労働収入として家計に合算し、実際の会社売上・法人会計や融資承認は再現しない。職種は自営、会社タイプはself、事業分野は選んだ内容に切り替える。転職または退職すると事業運営費は止め、売却益や清算費用は仮定しない。

企業資料は利用者が取得して確認する。掲載する要約は事業内容に限定し、将来の出来事や個人の待遇を根拠なく事実として付け足さない。

## 結果から次の年への分岐

開始時と各年の選択後に、接続先を問わずAIで自動生成する。毎年の確定結果と年収・純資産・ゆとり・つながりの差分を先に表示し、その結果・勤務先・家計・履歴から次の場面と4択を生成する。生成中は選択を止め、同じ年を重複して進めない。失敗は明示し、自動再試行やルール選択肢への切り替えはせず、その年で止める。クラウドは接続時の送信同意が必要。5/10年の進行も使えるが、途中の各年にはAIを呼ばない。

行動と結果の計算は検証可能なゲーム側に置く。学びやスキルで実証、成功で待遇の相談、経験で育成、事業の成長と現金100万円で追加投資、不調で方向転換、不調や資金・健康・失職で立て直し、事業中は撤退を解禁する。AIは現在許可された行動の中から、その年の具体的な提案を作る。定義外の更新や企業への応募・連絡は実行しない。Ollamaの出力には動的な行動enum付きJSON Schemaを指定し、返答も再検証する。小型モデルが残高と差分を取り違える場合があるため、生成文中の金額・割合の数値を含む文は使わず、正確な計算値は結果欄で示す。選択肢に金額を含めた場合はゲームで定義した費用説明を使う。

行動の成否は独立したseedチャネル31を使う。旧モデルの仕事の成果率は `0.35 + skill×0.004 + health×0.002` を0.2〜0.85へ制限。v0.3の成果率・事業不調率への補正は [確率モデル](probability-model.md) を参照。成功時の労働収入係数は実証・待遇相談1.10、他は1.025、実証の不調時は0.97、他は1。日常の休養・人との時間等には成果による追加倍率を付けない。

事業の不調率は `0.18 + (現金が生活費1年未満なら0.12) + AI普及×(1−skill/100)×0.12 + (拡大なら0.12) − (方向転換なら0.08)` を0.1〜0.55へ制限。不調で事業収入係数0.55・追加費用20万円、立て直しに成功するまでに不調が2度起きると撤退し、労働収入0・整理費15万円・運営費0とする。成功なら係数1.15（拡大は1.30）、不調回数を0に戻す。方向転換30万円、拡大100万円、自主撤退15万円。これらも実測の失敗率・統計モデルではない。撤退後の企業への転職は、収入0の場合に仮の基準180万円を使って再開できる。

既存v2セーブに `dynamicFrom` がなければ、保存されていた年数まで旧計算を保ち、再開年から新しい結果モデルへ切り替える。新しい保存ではその境界も保持し、巻き戻し・復元・比較の再計算をそろえる。開いたままの旧クライアントへは新しい行動IDを返さない。

退職年齢による選択肢・転職比較の制限は `retirementFrom` 以降に適用する。新規ゲームは0、項目のない旧セーブは記録済みの選択数+1とし、履歴と保存中の場面まで旧ルールで復元する。次の場面から新ルールを使い、この境界も保存・巻き戻し・世界比較で保持する。退職済みの状態を解除するものではない。

## キャリアの区切りまでの進行

新規ゲームは設定した退職年齢に達する年か、自分で仕事を離れた年に完結し、「わたしの履歴書」を表示する。以前のセーブで記録済みの退職後の年は保つ。これとは別に、年ごとに年齢・ゆとり・技術のシナリオから独自の死亡確率を計算する。`0.0005 × exp(max(年齢−35,0)/10) × (1+(50−ゆとり)/180) / (1+AI普及×0.08)` を0.0002〜0.6に制限。110歳で必ず終了する。これは公開生命表に較正しておらず、個人の寿命予測ではない。死因は作らない。終わりの年齢は開始前に表示しない。

転職・起業などの具体案は1年ずつ進む。繰り返せる方針は1年または5/10年の同じ重点で進行する。複数年進行でAIは自動呼び出ししない。途中で終了や行動条件の不成立になればそこで止まる。巻き戻しでは同じseedから再計算し、後続の選択と場面を破棄する。

別世界比較は初期条件・seed・選んだ行動を固定し、AIの普及速度を変える。別世界で先に終了した場合や、資金条件を満たさず行動できなくなった場合はその年までの結果を表示する。同じ行動を実行できた年だけで比較し、未実行の将来を勝手に補わない。生成文章は比較時に再生成せず、課金もしない。

## 信頼境界と通信

スマホ版は本人限定のWorkerが同じフロントエンドの8ファイルとAI APIを配信する。ビルドはHTMLに `mobile-cloud` の印を付け、PC専用の接続設定を隠す。CSPは同一オリジンと固定のWikidata APIへの接続を許可する。プロフィールと選択履歴をOpenAIへ送り、APIキーはサーバー側で管理する。セーブは任意でブラウザ内に保存し、PCへの自動同期はしない。静的ファイルだけでは新しい場面を生成できず、手動JSON交換も使えない。現行サーバーは `choiceVersion: 1` のない生成要求を拒否する。既存のキーを保持するためにサーバーを強制再起動しない。

HTTPは127.0.0.1にbind。Hostをlocalhost/127.0.0.1に限定し、静的ファイルは許可リスト。APIのPOSTは同一Origin、JSON、一時CSRFトークンを要求し、1MB・毎分60件まで。CORS許可を追加しない。CSPはブラウザの通信を同一オリジンに限定する。

会社ページはHTTPS・公開IPのみ。IPv4/IPv6の内部・予約アドレス、認証付きURL、非標準ポートを拒否する。DNSの全候補を検証し、接続先IPを固定して再解決によるすり替えを防ぐ。転送は2回まで、都度再検証。1ページ512KB、名前解決5秒、リクエスト15秒。HTMLはparse5でテキスト化し、実行しない。外部コンテンツは命令として解釈しない。

AI接続は利用者が設定したループバックまたはHTTPSの公開先だけ。リダイレクトは追跡しない。本文128KB・120秒、同時1件。APIキーをURL・ログ・保存・返答に含めない。プロンプトにツール・シェル権限を渡さない。費用と回数は [ai-and-costs.md](ai-and-costs.md) に記載する。

接続画面にはPCの種類・メモリを任意に選ぶローカルモデル案内を置く。M5・32GBの実測と他環境の未検証の目安を分け、選択したモデルや課金先を自動変更しない。生成中は経過時間を表示し、同じ接続の前回の成功時間を参考にする。時間はブラウザのメモリ内だけで保持し、キャッシュ・失敗は除く。品質の判定はJSONの受理だけで済ませず、勤務先・家族・直前の結果・行動の意味を比較する。[ローカルモデルの比較](local-models.md)を参照。サブスクのCodex CLI・Claude Code連携はPC版の毎年の自動生成として接続画面から選べる。制限と検証は[サブスクCLI連携](subscription-ai.md)を参照。

## 保存・検証・公開

セーブv2はプロフィール・世界・seed・選択・生成場面。新しい転職・起業は会社ID・職種または事業ID・名前等を持つ構造化した選択。既存v2の文字列の転職は従来の汎用ルールのまま再現し、実在企業へ自動変換しない。構造化データは復元時に候補・年・資金・文字数等を再検証する。勤務先や数値の派生状態は保存値を信用せず再計算する。最大250,000文字、選択と場面は110件まで。復元時は再検証・再計算する。旧v1は保持して書き出しを可能にし、黙って再計算しない。

`npm run check`をローカル・CIで共用し、合成データと一時ローカルHTTPのみで検証する。有料APIはCIで呼ばない。依存はnpm lockfile、外部ActionsはSHA固定、Dependabotと週次・手動のauditを維持する。GitHub上の検査成功と、実機のOllama確認・ブラウザ確認は別に記録する。

現在は非公開リポジトリのローカルアプリ。将来のOSS公開ではライセンスの確定、秘密情報と個人データの再確認、インストール手順、外部AIやモデルの利用条件を確認する。個人情報を含む公開の投稿機能やランキングは要件に追加しない。

スマホ版の認証・累計上限・検証と配備手順は[本人限定のWorkerとD1を使うOpenAI版](../hosted/README.md)を参照。累計2000回または見積り$5で停止し、再配備でリセットしない。
