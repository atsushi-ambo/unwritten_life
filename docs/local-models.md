# ローカルモデルの比較

確認日：2026-10-17。対象は、このゲームの日本語の場面と選択肢の生成です。一般的なモデルの総合順位や、人生の予測精度を測る試験ではありません。

このMacBook Air M5・32GBでは、文章の具体性と待ち時間、メモリの余裕のバランスから **`gemma4:12b-it-q4_K_M` を推奨**します。既存の軽い `qwen3:8b` も残せます。選ぶときはゲームの「AIの接続」→Ollamaのダウンロード済み一覧を使います。既存のクラウドの設定や利用中のセーブを、この検証のために切り替える必要はありません。

現行のゲームと同じ指示での実測です。時間には各モデルの初回ロードを含みます。

| モデル                      | ファイル | 受け入れた場面 | 1場面の時間    | 観測したswap使用量 |
| --------------------------- | -------- | -------------- | -------------- | ------------------ |
| Qwen3 8B                    | 約5.2GB  | 5/5            | 中央値19.3秒   | 0                  |
| Gemma 4 12B Q4_K_M          | 約8.0GB  | 5/5            | 中央値31.0秒   | 0                  |
| Qwen3.8 27B Q4_K_M・MTP設定 | 約17.7GB | 完了した2/2    | 71.5秒・92.2秒 | 約2〜3GiB増加      |

大きいQwenはメモリへの負担が増えたため、3場面目の途中で検証を止めてアンロードしました。未完了の3場面を成功とも失敗とも数えず、5場面の中央値とも比較しません。他のアプリや使用条件が変われば結果も変わります。このPCの普段のゲーム用にはGemmaを選び、より大きいモデルを動かすためのOSのメモリ設定変更や他のアプリの終了は行っていません。

## このPCでの候補

Apple M5・メモリ32GB、Ollama 0.40.5。既存の `qwen3:8b` に加え、Qwen3.8 27BとGemma 4 12Bの4bit版を候補とします。モデルの重みをGitに入れず、利用者自身のOllamaへ取得します。

- [Qwen3.8の公式モデルカード](https://huggingface.co/Qwen/Qwen3.8-27B)、[Ollamaのタグ](https://ollama.com/library/qwen3.8/tags)
- [Gemma 4 12Bの公式モデルカード](https://huggingface.co/google/gemma-4-12B)、[Ollamaのタグ](https://ollama.com/library/gemma4/tags)

両候補の公式モデルカードはApache-2.0を指定しています。アプリ自体の公開・ライセンスの決定とは別です。

Ollama 0.40.5はApple SiliconでMLXのモデルを優先する場合があります。このPCのHomebrew版ではMLX用の `libollama_xgrammar.dylib` が含まれていません。ゲームに必要な構造化出力を使うため、比較対象にはGGUFの明示的なタグを使います。別のOllama配布物や将来の版まで同じ状態とは限りません。[選択の実装](https://github.com/ollama/ollama/blob/v0.40.5/manifest/manifest.go)、[構造化出力の実装](https://github.com/ollama/ollama/blob/v0.40.5/mlxrunner/grammar.go)。

```sh
ollama pull gemma4:12b-it-q4_K_M
ollama pull qwen3.8:27b-mtp-q4_K_M
```

## 再実行

比較スクリプトはmacOS用の手動検証です。起動中のゲームサーバーやそのAPIキーを読み込まず、固定の `127.0.0.1:11434` にだけ生成を依頼します。クラウドモデルと未取得モデルは拒否し、モデルの自動取得も行いません。ゲームのプロフィール・セーブ・AI設定・利用回数を変更しません。

```sh
npm run benchmark:local -- qwen3:8b current
npm run benchmark:local -- gemma4:12b-it-q4_K_M current
npm run benchmark:local -- qwen3.8:27b-mtp-q4_K_M current
```

他の推論が走っていないときに、1コマンドずつ実行してください。開始時にロード済みのモデルがあれば検証を始めずに終了し、自動で他のモデルをアンロードしません。開始後は同じモデルで場面を順番に生成し、終了時にそのモデルだけアンロードします。

合成プロフィールによる5場面を使います。

1. 地方都市の賃貸に暮らす技術職の初年度。
2. 毎日の学びが評価されたが、国際紛争の影響で年収が下がる年。
3. 起業して顧客の手応えを得ても、前職より年収が下がる年。
4. 事業に失敗して撤退し、次の仕事を探す年。
5. 子どもが2人いる家庭で、3人目を考える希望だけを更新した年。

同じゲームの状態・生成seed・temperature 0.7・コンテキスト8192・最大出力1500token・推論オフ・動的な行動IDのJSON Schemaを使います。1回120秒で打ち切り、失敗時の自動再試行はしません。出力、補正前後の違い、モデルdigest、時間、ロード中のOllamaのメモリ情報、OSのメモリ余裕とswapを、Git対象外の `artifacts/local-*.json` へ保存します。メモリは場面終了時の観測で、ピーク値ではありません。

今回のQwenの観測を受け、スクリプトには各場面の終了時に、開始前よりswap使用量が1GiB以上増えた場合、またはOSの空き表示が10%未満になった場合、残りを中止する制限を追加しました。モデルを解放して記録を保存し、終了コード2を返します。生成・検証に失敗した場合は終了コード1です。この制限は比較スクリプト用で、ゲームやOllama全体のメモリ設定を変えません。

追加した停止判定は、保存した正常・高負荷のログと1GiB・10%の境界値で確認しました。実機へ再度負荷をかける自動停止の再試験は行っていません。今回のQwenの停止は手動です。

指定しないtop_p等は各モデルの既定値を使います。モデルの既定パラメーターも記録し、完全に同一のサンプリング条件でのモデル単体比較とは区別します。ゲームの実際の設定で遊べるかを確かめるための比較です。

`current` はゲームと同じプロンプトです。`focused` は確定した成否・家族・年収変化を先頭で強調した実験用の短い指示、`narrative` はそれに加えて、金額を生活費に対する余裕などの表現へ置き換えて渡す実験です。後二者は比較スクリプト内だけで使い、ゲーム本体へ自動反映しません。

```sh
npm run benchmark:local -- gemma4:12b-it-q4_K_M focused
npm run benchmark:local -- gemma4:12b-it-q4_K_M narrative
BENCH_SEED=2027 npm run benchmark:local -- gemma4:12b-it-q4_K_M current
```

## 評価の読み方

JSONとして成功しても、良い物語とは限りません。現在の会社、住まい、学び、家族の人数、年収の増減、景気やAIとのつながりを、補正前の文章も読んで確認します。以下の会社名の件数・本文の長さは補正前の値です。ゲームの `groundScene` が矛盾や数字で書かれた金額を除いた回数と、ルールの本文へ戻した回数を分けて記録します。補正後の成功だけをモデルの正確さとして数えません。

5場面・固定seedの小さな比較なので、全プロフィールでの安定性や別のMacでの速度は保証しません。バックグラウンドの処理、モデルのロード、温度、Ollamaの更新でも速度が変わります。モデル名だけでなくdigestと設定を合わせて再確認してください。

## 既存のQwen3 8Bでのプロンプト比較

生成seedは2026、各5場面。時間は初回ロードを含む全5回の中央値です。

| 指示      | 受け入れ可能なJSON | 時間中央値 | 本文の補正 | 就業中の本文に会社名 |
| --------- | ------------------ | ---------- | ---------- | -------------------- |
| current   | 5/5                | 19.3秒     | 5/5        | 1/4                  |
| focused   | 5/5                | 22.0秒     | 2/5        | 1/4                  |
| narrative | 5/5                | 20.4秒     | 0/5        | 0/4                  |

`qwen3:8b` のdigestは `500a1f067a9f`、ファイル約5.2GB、推論中のOllamaの使用量は約5.8GB（100% GPU、8192 context）。観測時のswap使用量は0でした。

この試行では短い指示と相対的な家計情報によって金額の転載は減りましたが、会社名が抜ける問題は改善しませんでした。`narrative` では、事業失敗を自分から閉業した選択のように書く場面もありました。どの指示でも本文は指定した200〜350字に達していません。したがって、補正回数だけを根拠にこの実験用プロンプトへ置き換えません。

## Gemma 4 12Bの観測

`gemma4:12b-it-q4_K_M`、digest `6114515d63c1`、ファイル約8.0GB。現行の指示では5/5場面を受け入れ、時間の中央値は31.0秒（27.2〜45.0秒）。補正前の本文は229〜262字で、就業中の会社名は3/4場面に含まれました。事業の撤退や、希望を更新しただけでは子どもが増えていない点も描けています。

本文の自動補正は1/5場面でしたが、別の1場面では「九百万円」と漢数字で金額を書き、既存の数値フィルターを通過しました。初年度の会社名の省略、株式へ移す選択を「守り」と表現した点も残ります。補正が少ないことを、すべての指示に従った証拠としては扱いません。

検証中の観測では、推論プロセスのRSSは約11.3GB、OSのメモリ余裕の表示は31〜35%、swap使用量は0でした。RSSは1時点の観測であり、GPU等を含む総使用量やピーク値ではありません。Ollamaの`/api/ps`に出るサイズだけでは、この環境のモデル全体の使用量を判断しません。

| 指示      | 受け入れ可能なJSON | 時間中央値 | 本文の補正 | 就業中の本文に会社名 |
| --------- | ------------------ | ---------- | ---------- | -------------------- |
| current   | 5/5                | 31.0秒     | 1/5        | 3/4                  |
| focused   | 5/5                | 34.5秒     | 2/5        | 4/4                  |
| narrative | 5/5                | 35.5秒     | 0/5        | 4/4                  |

短い指示では会社名の反映は増えた一方、1場面の選択肢説明に無関係な英語の断片が混ざりました。これはJSONとしては正常な文字列に入っており、構造化出力だけでは防げません。相対的な家計情報に置き換えた指示でも、資金に余裕がある条件を乏しいと描く場面が残りました。今回の5場面だけで、実験用の指示を本体の既定値へ反映しません。

現行のアプリの接続処理 `makeAI` でも、架空の家計と持ち家・家族を使い、Microsoftへ転職した2037年、実証が不調だった2038年、66歳の退職後の3場面を実生成しました。2038年は直前の不調や子どもの成長が本文に反映され、選択肢の行動IDも変わりました。これはブラウザの操作試験ではなく、合成セーブ→実際のOllama→アプリの出力検証という接続試験です。利用中のサーバーとは別のAIインスタンスを使い、OpenAIの設定・キー・利用回数・実際のセーブを変更していません。

## Qwen3.8 27Bの観測

比較したタグは `qwen3.8:27b-mtp-q4_K_M`、digest `22130167c4c2`。通常版 `qwen3.8:27b-q4_K_M` と重みを共有し、MTP設定だけを追加したタグです。このPCには両方のタグを取得しました。タグごとに重みの全量を重複保存するものではありません。

完了した2場面はJSONとして受け入れ、会社や年収の減少、家族が未定という条件も反映しました。ただし、1場面目の金額を含む文を補正すると、会社名を含む文も除かれました。2場面目の漢数字の金額は既存のフィルターを通過しました。大きいモデルでも、今回の指示で金額の転載や結果を保証する表現がなくなるわけではありません。

検証前のswap使用量は0で、読み込み後に約2.2GiB、3場面目の途中には約2.9GiBへ増えました。OSのメモリ余裕の表示は14〜16%、観測した推論プロセスのRSSは約18GBでした。ここで比較プロセスと、そのモデルだけを停止しました。モデル解放後、Ollamaのロード済み一覧は空、OSの空き表示は76%に戻りました。OSが保持するswapを強制的に消去したり、PCを再起動したりはしていません。
