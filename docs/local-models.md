# ローカルモデルの比較

確認日：2026-10-17。対象は、このゲームの日本語の場面と選択肢の生成です。一般的なモデルの総合順位や、人生の予測精度を測る試験ではありません。

このMacBook Air M5・32GBでは、文章の具体性と待ち時間、メモリの余裕のバランスから **`gemma4:12b-it-q4_K_M` を推奨**します。既存の軽い `qwen3:8b` も残せます。選ぶときはゲームの「AIの接続」→Ollamaのダウンロード済み一覧を使います。既存のクラウドの設定や利用中のセーブを、この検証のために切り替える必要はありません。

## 接続画面の案内

PC版の「このPCで使うモデルの選び方」でPCの種類と搭載メモリを選ぶと、候補と未確認の条件を表示します。自動のハードウェア診断や動作保証ではありません。指定はその画面内だけで使い、セーブ・AIへの送信・モデルの取得・接続設定の変更には使いません。Windows・Linux・Intel MacではGPUやVRAM等も必要なので、RAMだけでモデルを推奨しません。16・24GBでは最低要件が未検証と表示します。8GB以下での動作も今回の32GB機の試行から推奨せず、小型モデルでも日本語・4択の質と実行メモリを別々に確認する必要を表示します。

生成中は経過時間を表示し、同じ接続先・モデルで成功した前回の待ち時間も参考として表示します。キャッシュ、失敗、古いゲーム状態への返答は記録しません。履歴は画面のメモリ内だけに置き、再読み込みで消えます。表示は実際の完了時刻や残り時間の予測ではなく、生成の途中段階を推測した進捗率も出しません。生成の速さを上げるために出力検証を省いたり、失敗時に別の有料APIへ切り替えたりはしません。

## 最新の4択での追加比較

合成プロフィール5場面・seed 2026、現在の `storyRequest` と厳密な4択の `sceneSchema` を使用します。Gemmaの再測定は5/5を構造上受け入れ、36.8〜64.7秒、中央値41.1秒でした。開始前からOSに約2.6GiBのswapが残っていましたが、この実行での増加はありません。生成中10秒ごとの観測と終了時のメモリ余裕は25%以上でした。モデル取得をバックグラウンドで実行しているため、待ち時間は普段の環境での参考値です。

Gemmaの日本語は自然で、事業の撤退、学習の手応え、家族を迎える「希望」を反映しました。本文は指定の120〜200字の範囲内の140〜169字でした。一方、2/5で金額の自動除去がありました。「現金の大部分」と「一部」が混在する投資の意図や、企業名の欄に受託案件の一般名が入る選択も残りました。5/5は出力契約の受け入れ数であり、全選択肢の内容が正確という評価ではありません。この比較だけで既存モデルを自動で切り替えません。

Qwen3 8Bは最新4択では2/3場面を受け入れ、3場面目の「テクノロジー企業」という一般名を実在企業として返したため拒否して停止しました。残り2場面は未実行です。初年度も会社名の代わりに部署名を返し、本文は74〜90字と短く、本人の条件より一般的な説明が目立ちました。旧形式で5/5通った結果を、最新4択の安定性とは扱いません。

GLM-4 9B Chat Q4_K_M（digest `f17dc1ac3c7c`）も最新4択で5/5場面を受け入れました。39.4〜88.6秒、中央値75.7秒で、この試行ではGemmaより待ちました。観測したメモリ余裕は58%以上でswapの新たな増加はありません。小さなファイルが速い生成を保証するわけではありません。

ただし5/5の本文で金額の除去が必要でした。初年度・起業直後・撤退後の場面は補正前でも120字未満で、会社名の反映は就業中の1/4場面に限られます。選択肢は入力の行動説明の転載が多く、「住居費が安い」と言いながら高い住居費を続けて書く移住の意図や、「逆風に乗る」という不自然な表現もありました。家族の希望を更新しただけで出生が確定していない点は描けていますが、今回のゲーム用にGemmaから切り替える利点は見つかりませんでした。これは旧GLM-4 9Bの結果で、GLM-4.6VやGLM-4.7-Flashの実測ではありません。

Llama 3.2 3B（digest `a80c4f17acd5`、約2.0GB）は3/4場面を受け入れ、4場面目で最大1500tokenに達してJSONがUnicodeエスケープの途中で途切れました。5場面目は未実行です。受け入れた3場面は14.7・25.1・56.4秒、失敗した4回目は67.4秒でした。観測したメモリ余裕は69%以上で、swapの増加はありません。

形式を受け入れた3場面も、本人の31歳を32歳と書く、住居費を「月の現金」と取り違える、説明用の「入力と世界の関係を60文字以内」を返す、本文に空の番号や長い解説を並べるなど、ゲーム用の日本語と事実の扱いが弱い結果でした。本文の金額の自動除去は3/3で必要でした。小型Metaモデルで日本語を生成すること自体はできますが、今回のプロンプト・上限で普段のゲーム用に採用しません。Llama全体やMuseの評価ではありません。

## 再実行

比較スクリプトはmacOS用の手動検証です。起動中のゲームサーバーやそのAPIキーを読み込まず、固定の `127.0.0.1:11434` にだけ生成を依頼します。クラウドモデルと未取得モデルは拒否し、モデルの自動取得も行いません。ゲームのプロフィール・セーブ・AI設定・利用回数を変更しません。

```sh
npm run benchmark:local -- qwen3:8b current
npm run benchmark:local -- gemma4:12b-it-q4_K_M current
npm run benchmark:local -- qwen3.8:27b-mtp-q4_K_M current
```

他の推論が走っていないときに、1コマンドずつ実行してください。開始時にロード済みのモデルがあれば検証を始めずに終了し、自動で他のモデルをアンロードしません。開始後は同じモデルで場面を順番に生成し、終了時にそのモデルだけアンロードします。

合成プロフィールによる5場面を使います。

1. 地方都市の賃貸に暮らす技術職の初年度。
2. 毎日の学びが評価されたが、国際紛争の影響で年収が下がる年。
3. 起業して顧客の手応えを得ても、前職より年収が下がる年。
4. 事業に失敗して撤退し、次の仕事を探す年。
5. 子どもが2人いる家庭で、3人目を考える希望だけを更新した年。

同じゲームの状態・生成seed・temperature 0.7・コンテキスト8192・最大出力1500token・推論オフ・動的な行動IDのJSON Schemaを使います。1回120秒で打ち切り、失敗時の自動再試行はしません。出力、補正前後の違い、モデルdigest、時間、ロード中のOllamaのメモリ情報、OSのメモリ余裕とswapを、Git対象外の `artifacts/local-*.json` へ保存します。メモリは生成中に10秒ごとと場面終了時に観測します。短時間のピークを捕捉するものではありません。旧試行は場面終了時だけの観測です。ファイル名に実行日時を付け、別の実行結果を上書きしません。

今回のQwenの観測を受け、スクリプトには生成中と各場面の終了時に、開始前よりswap使用量が1GiB以上増えた場合、またはOSの空き表示が10%未満になった場合、その生成と残りを中止する制限を追加しました。以前の実行後にOSが保持しているswapは、今回のモデルが増やした量には数えません。モデルを解放して記録を保存し、終了コード2を返します。生成・検証に失敗した場合は終了コード1です。この制限は比較スクリプト用で、ゲームやOllama全体のメモリ設定を変えません。

追加した停止判定は、保存した正常・高負荷のログと1GiB・10%の境界値で確認しました。実機へ再度負荷をかける自動停止の再試験は行っていません。今回のQwenの停止は手動です。

指定しないtop_p等は各モデルの既定値を使います。モデルの既定パラメーターも記録し、完全に同一のサンプリング条件でのモデル単体比較とは区別します。ゲームの実際の設定で遊べるかを確かめるための比較です。

`current` はゲームと同じプロンプトと個人に合わせた厳密な4択です。`focused`・`narrative` は旧式の3〜5択用で、その旧契約のSchemaと検証を使います。厳密な4択の評価には含めません。`focused` は確定した成否・家族・年収変化を先頭で強調した実験用の短い指示、`narrative` はそれに加えて、金額を生活費に対する余裕などの表現へ置き換えて渡す実験です。後二者は比較スクリプト内だけで使い、ゲーム本体へ自動反映しません。

```sh
npm run benchmark:local -- gemma4:12b-it-q4_K_M focused
npm run benchmark:local -- gemma4:12b-it-q4_K_M narrative
BENCH_SEED=2027 npm run benchmark:local -- gemma4:12b-it-q4_K_M current
```

## 評価の読み方

JSONとして成功しても、良い物語とは限りません。現在の会社、住まい、学び、家族の人数、年収の増減、景気やAIとのつながりを、補正前の文章も読んで確認します。以下の会社名の件数・本文の長さは補正前の値です。ゲームの `groundScene` が矛盾や数字で書かれた金額を除いた回数と、ルールの本文へ戻した回数を分けて記録します。補正後の成功だけをモデルの正確さとして数えません。

5場面・固定seedの小さな比較なので、全プロフィールでの安定性や別のMacでの速度は保証しません。バックグラウンドの処理、モデルのロード、温度、Ollamaの更新でも速度が変わります。モデル名だけでなくdigestと設定を合わせて再確認してください。
